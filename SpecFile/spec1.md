# Gemini API Key 測試頁面開發規格書

## 1. 文件目的與目前狀態

本文件將需求大綱整理為後續開發與驗收依據。目標是在現有 .NET 10 ASP.NET Core Razor Pages 專案中，以本機檔案提供一組 Gemini API Key，輸入文字後取得文字回覆，確認 Key 與 API 呼叫流程正常。

目前專案為起始應用程式，尚未實作本文件描述的功能。本次僅完善規格書，不修改程式、設定檔或 `.gitignore`，不建立 Key 檔案、不進行真實 API 呼叫。以下程式與設定要求均為後續開發要求。

## 2. 需求來源與決策

### 2.1 原始需求大綱

以下保留原始五點需求，後續章節將其具體化：

1. 首頁上方新增一個超連結名稱為「API Key 測試頁面」，點擊後會導向到 API Key 測試頁面。
2. 專案跟目錄新增一個檔案裡面儲存 API Key 此檔案不能上傳至 GitHub，並且要加入 .gitignore。該檔案內容不需要太複雜只需要提示key在哪邊輸入即可以及只能輸入一組
3. 此功能頁面要去上述項目2的檔案裡面讀取 API Key，帶入該功能頁面使用.
4. 該功能要面上下方各一個對話匡, 上方用途是使用者輸入的內容, 下方用途是顯示回傳的結果.
5. 版面不需要太華麗本頁面單純測試 API Key 呼叫的功能而已, 最重要是能夠正常呼叫 API Key 並且回傳結果顯示在下方對話匡即可.

### 2.3 本規格採用的預設值

以下為開發預設值，與原始需求及已確認決策分開記錄：

| 項目 | 預設值 |

## 3. 第一版功能範圍

包含首頁導覽入口、簡單測試頁面、讀取單一 Key、單次文字生成、結果顯示、錯誤提示及必要診斷資訊。

不包含登入、多人管理、多組 Key、頁面上輸入或編輯 Key、聊天歷史、資料庫、串流、圖片／音訊／檔案上傳、工具呼叫、模型選單及用量統計。每次測試只傳送當次輸入，不帶入先前問答。

服務限本機存取，不增加對外監聽設定。未來若開放多人或公開使用，須另行制定存取控制、用量限制與部署規格。

## 4. 頁面與使用流程

### 4.1 導覽與版面

- 共用頂部導覽列新增「API Key 測試頁面」，導向 `/ApiKeyTest`，保留既有導覽。
- 頁面標題為「API Key 測試頁面」，沿用現有 Bootstrap 與共用版面，不加入新 UI 套件。
- 上方為標示「輸入內容」的可編輯多行文字框，下方為標示「回傳結果」的唯讀多行文字框。
- 中間提供「送出測試」按鈕及狀態訊息；窄螢幕仍上下排列。
- 簡短提示 Key 從本機檔案讀取、輸入會送至 Gemini、每次為獨立測試；不顯示 Key 或其部分內容。
- 結果以純文字呈現，保留換行，允許捲動、選取與複製，不解析 HTML 或 Markdown。

### 4.2 狀態與操作順序

| 狀態 | 畫面與行為 |
| --- | --- |
| 初次開頁 | 輸入與結果為空，按鈕可用，不呼叫 Gemini |
| 驗證失敗 | 保留輸入、清除舊結果、顯示提示，不呼叫 Gemini |
| 處理中 | 保留輸入、清除舊結果、顯示「處理中…」、停用送出按鈕 |
| 成功 | 顯示文字回覆及「測試成功」，恢復按鈕 |
| 截斷 | 保留已取得文字，提示「回覆已達長度限制，內容可能不完整」，恢復按鈕 |
| 失敗 | 結果為空，狀態區顯示錯誤摘要，恢復按鈕 |

採 Razor Pages 表單 POST。前端驗證通過才進入處理中狀態，後端仍重新驗證，不能僅依賴 JavaScript。錯誤後可修改輸入或 Key 檔案再測試，不需重啟。

停用按鈕避免同頁連續點擊，不提供跨分頁去重。重新整理 POST 結果頁時，若使用者確認瀏覽器的重新提交提示，可能再次呼叫 API。

### 4.3 輸入驗證

- 不接受空字串、只有空白或換行的內容，提示「請輸入要測試的文字」。
- 前後端均限制最多 4,000 個 UTF-16 code unit；超長提示「輸入內容不可超過 4,000 個字元」，不默默截斷。
- 長度以原始輸入計算，合法輸入與換行原樣傳送。

## 5. Key 檔案規格與保護

### 5.1 路徑與格式

以 `ContentRootPath` 定位專案根目錄的 `gemini-api-key.txt`，不以目前工作目錄推算，不接受使用者提交的路徑，不放在 `wwwroot`。

檔案使用 UTF-8，允許 UTF-8 BOM、LF 或 CRLF。格式如下，範例僅含占位文字：

```text
# 請將下一行替換為一組 Gemini API Key，不需加引號。
YOUR_GEMINI_API_KEY
```

使用者在下一行填入實際 Key；不使用 JSON、`key=` 或引號，只允許一組 Key。

### 5.2 讀取規則

1. 每次合法表單送出後重新讀取，不將 Key 固定快取至應用程式結束。
2. 去除每行前後空白，忽略空白行與以 `#` 開頭的註解行，不支援行尾註解。
3. 剩餘內容須恰有一行，且不可為 `YOUR_GEMINI_API_KEY`。
4. 不以固定長度或前綴判斷 Key 有效性，以遠端認證結果為準。
5. 缺檔、無有效值、多行有效值、未替換占位文字、讀取失敗或內容無法安全作為認證標頭時，顯示設定錯誤，不發出 Gemini 請求。
6. 缺檔時提示檔案名稱與格式，不自動建立檔案，不顯示檔案內容或完整實體路徑。

### 5.3 後續開發順序與保護

- 先在 `.gitignore` 加入根目錄限定規則 `/gemini-api-key.txt`，確認生效後才建立占位檔案。
- 確認 Key 檔案未被 Git 追蹤；忽略規則不會自動取消已追蹤檔案。
- 明確排除建置輸出與發佈複製，驗證輸出目錄不含此檔案。
- Key 不得進入程式、版本控制、前端資產、隱藏欄位、網址、日誌、截圖或錯誤訊息。
- HTTP 用戶端診斷日誌須遮蔽 `x-goog-api-key`，不得記錄完整請求／回應本文。
- 設定檔僅保存非機密模型名稱，不提供其他 Key 來源。

## 6. 後端責任與 Gemini 介面

### 6.1 元件責任

| 元件 | 責任 |
| --- | --- |
| Razor Page 與 PageModel | GET 顯示頁面；POST 驗證輸入、呼叫服務、顯示結果與狀態；保留防偽權杖驗證 |
| Key 讀取服務 | 從固定路徑讀取與驗證 Key，回傳可處理的設定錯誤 |
| Gemini 呼叫服務 | 使用 `IHttpClientFactory` 建立的用戶端，非同步送出 HTTP、解析回應與分類錯誤 |
| 非機密設定 | 在 `appsettings.json` 以 `Gemini:Model` 指定模型 |

頁面只提交輸入與框架防偽資訊，Key 及模型由後端決定。不建立獨立公開 API 端點，不讓瀏覽器直接呼叫 Gemini。

### 6.2 模型設定

後續開發加入以下非機密設定：

```json
{
  "Gemini": {
    "Model": "gemini-2.5-flash"
  }
}
```

未提供設定時使用預設模型；明確設定空白或不合法模型識別字時顯示設定錯誤。模型值只能是識別字，不得包含 URL、`models/` 前綴或其他路徑。切換方式為修改設定後重新啟動，不要求設定熱更新；模型不可用時不自動改用其他模型。

### 6.3 HTTP 請求

依 [Gemini generateContent 官方介面](https://ai.google.dev/api/generate-content) 使用：

```http
POST https://generativelanguage.googleapis.com/v1beta/models/{model}:generateContent
Content-Type: application/json
x-goog-api-key: <由後端從本機檔案讀取>
```

請求本文範例：

```json
{
  "contents": [
    {
      "role": "user",
      "parts": [
        { "text": "請用繁體中文簡短介紹你能協助的事情。" }
      ]
    }
  ]
}
```

使用 JSON 序列化處理引號、換行與 Unicode，不拼接 JSON。依 [Gemini API Key 官方文件](https://ai.google.dev/gemini-api/docs/api-key)使用標頭認證，不將 Key 加入查詢字串。

HTTP 逾時為 60 秒，支援取消，不自動重試。第一版沿用服務預設生成參數與安全門檻，不另加工具，不傳送歷史或額外指令。

### 6.4 回應解析

- 檢查 HTTP 狀態再解析結構化回應；HTTP 200 不代表一定有可顯示文字。
- 檢查 `promptFeedback.blockReason` 及第一個候選的 `finishReason`，辨識阻擋與結束原因。
- 從第一個候選的 `content.parts` 依序取出一般 `text` 片段並直接串接，保留片段內換行；排除 `thought: true` 及非文字片段。
- 一般完成且有非空白文字才標為成功。無候選、無一般文字或只有空白時提示「API 未回傳可顯示的文字」。
- `MAX_TOKENS` 有文字時保留文字並提示截斷；無文字時顯示無文字提示及長度限制原因。
- 安全阻擋時不顯示候選內容。其他非正常結束或無法解析的回應視為回應異常，不標示成功。

## 7. 錯誤處理與診斷

錯誤摘要使用繁體中文，與結果分開顯示，參照 [Gemini 官方疑難排解文件](https://ai.google.dev/gemini-api/docs/troubleshooting)分類，不將所有失敗都判定為 Key 無效。

| 情境 | 提示與處理 |
| --- | --- |
| Key 檔案或模型設定有誤 | 提示設定項目與修正方向，不呼叫 Gemini |
| HTTP 400 | 提示請求或服務設定不符；結構化錯誤可辨識為 Key 問題時改顯示認證提示 |
| HTTP 401／403 | 提示認證失敗或權限不足，檢查 Key 與 API 存取限制 |
| HTTP 404 | 提示模型或 API 資源不存在，檢查 `Gemini:Model` |
| HTTP 429 | 提示頻率或配額限制，稍後重試或檢查配額 |
| HTTP 5xx | 提示 Gemini 服務暫時異常，稍後再試 |
| DNS、連線或 TLS 失敗 | 提示無法連線至 Gemini，檢查網路 |
| 超過 60 秒 | 提示請求逾時，可再次測試 |
| 安全阻擋 | 提示內容遭阻擋，可調整輸入再試 |
| 無可用文字、異常 JSON 或非正常結束 | 顯示對應回應摘要，不輸出原始本文 |
| 其他非成功狀態或未預期例外 | 顯示一般失敗提示，不洩漏內部細節 |

自訂診斷日誌只記錄錯誤類別、HTTP 狀態（若有）與耗時，不記錄 Key、輸入、回覆、檔案內容、原始錯誤本文或堆疊。瀏覽器中止時取消後端工作，不將使用者中止誤報為逾時。
